1. 项目背景与目标
构建一个基于C++17规范的无人机机载智能程序，建议命名空间plane
运行环境：系统ubuntu22.04,支持X64和arm64架构;硬件是基于3588芯片的智能板，通过串口或网口（UDP）与飞控通信
使用场景：控制己方基于PX4的火箭穿越机无人机进行自杀式反制其他无人机
第一版本必须支持PX4；第一版本不要求支持APM，后续可扩展。

2.核心功能：
自杀式反无任务：解锁+起飞+中段制导+目标检测+单目标跟踪+导引撞击
单机控制指令：解锁、上锁、起飞、降落、返航、航点飞行、航线飞行、悬停、停桨等
第一版本不维护任务/指令等待队列，系统始终执行最新收到的任务或指令。

4).建议的模块划分：
通信模块：基于zenohcpp实现与地面站及其他飞机的无线通信，核心收发 API: sendToStation、sendToplane、sendToAll，优先点对点、避免广播。按可配置周期上报本机状态与当前任务状态。
序列化机制: 通信模块接受外部 std::string，根据messagetype字段将内容反序列化为nlohmann::json-->class 对象，放进消息总线分发给具体业务模块。json 不出通信模块。
消息总线: 使用eventcpp 做内部异步事件。同级模块严禁交叉引入对方实现头文件；允许依赖稳定能力接口做同步查询/调用。异步联动注册唯一 Event ID，发布/订阅解耦。
状态管理: 存储本机、其他无人机以及地面站状态上下文（空速、电压、当前经纬度）
任务管理: 接收地面站下发的任务意图（不含 Command 序列、不含行为树结构），由机载按任务类型映射到行为树执行。第一版本不维护任务/指令等待队列，始终执行最新收到的任务或指令。
目标管理: 汇集视觉算法与地面站给出的目标信息（置信度等）。第一版本不接入雷达目标；不对目标轨迹做平滑；不要求将视觉目标转换为经纬度；视觉目标维护图像位置即可。
系统参数: 安全高度等由配置维护，启动时加载默认值，运行中可由地面站动态下发。不单独设立场景管理模块。第一版本不要求盘旋半径、电子围栏、禁飞区。
SceneMonitor (场景监控器): 监控飞机安全底线（电压异常、姿态异常）,异常时发布告警。
行为树执行: 行为树执行模块
图像处理: 从MIPI读取图像；相机建联、状态获取、控制指令下发；按任务阶段调用目标检测、单目标跟踪、图像导引。不单独设立相机控制模块。
视频推流: 独立于图像处理，经zlmediakit对外RTSP推流。
飞行控制： 连接飞控，负责无人机的具体操作下发，比如起飞 航线 动作等。第一版本对接PX4。
